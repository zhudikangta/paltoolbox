# 幻兽帕鲁 1.0 数据与资源整理设计

## 目标

明确游戏程序与游戏版本内容的边界，将 1.0 版本的数据包和资源包统一放入 `游戏内容/幻兽帕鲁1.0`，让不带版本号的 `游戏内容/幻兽帕鲁` 只保存不随游戏版本切换的程序、界面、样式、外部库和界面资源。

本次整理同时完成以下事项：

- 把仍在使用的旧数据迁入 1.0 数据包。
- 删除已经由 1.0 数据替代且不再被业务读取的旧数据。
- 删除过时的旧地图背景瓦片，保留并迁移仍被地图使用的标记图标。
- 按用途整理 1.0 图片，清除明确重复和错放的副本。
- 将明确的 NPC 图片归入人物头像。
- 将无法确认用途的图片保留在带原分类名称的待确认目录中。
- 更新所有运行引用、迁移验证和项目结构说明。

## 目录职责

整理后的职责如下：

```text
游戏内容
├── 幻兽帕鲁
│   ├── 工具功能：不随游戏版本切换的核心、通用逻辑和模式适配
│   ├── 外部库：游戏工具当前使用的第三方程序
│   └── 界面资源
│       └── 壁纸：工具箱界面使用的背景和标志图片
└── 幻兽帕鲁1.0
    ├── 数据包：1.0 版本正式数据和计算配置
    └── 资源包
        ├── 地图
        │   └── 瓦片
        ├── 地图图标
        ├── 地图图标待确认
        ├── 帕鲁头像
        ├── 帕鲁头像待确认
        ├── 人物头像
        ├── 物品图标
        ├── 物品图标待确认
        ├── 建筑图标
        ├── 建筑图标待确认
        ├── 技能图标
        ├── 技能图标待确认
        ├── 属性图标
        ├── 属性图标待确认
        ├── 工作图标
        └── 工作图标待确认
```

只在确实存在无法确认的文件时建立对应待确认目录，不建立空目录，也不建立失去来源语境的总 `待确认` 目录。

未来出现 2.0 版本时，新增 `游戏内容/幻兽帕鲁2.0/数据包` 和 `资源包`；程序和界面继续复用 `游戏内容/幻兽帕鲁`。

## 数据包整理

### 继续使用的数据

`游戏内容/幻兽帕鲁/数据包/工作速度计算器数据.js` 仍被工作速度核心和通用逻辑直接读取。将其迁入 `游戏内容/幻兽帕鲁1.0/数据包`，保持数据结构、计算因子和现有同步加载方式不变，只更新浏览器入口与 CommonJS 测试环境的引用路径。

本次不改工作速度公式，不顺带把 JavaScript 数据改成 JSON，避免把目录整理扩大成加载方式改造。

### 删除的数据

以下三个旧数据文件只在入口和迁移脚本中被加载或强制保留，业务代码不读取它们：

- `物品数据.js`
- `装备数据.js`
- `建筑数据.js`

当前物品和建筑来自 1.0 JSON；装备从 1.0 物品数据中按类别建立索引。删除这三个旧文件，并同步删除入口脚本标签、迁移复制清单和完整性检查中的旧要求。

### 数据唯一入口

整理后，所有版本事实都从 `幻兽帕鲁1.0/数据包` 进入网站。`幻兽帕鲁` 下不再保留 `数据包` 正式目录。

## 资源包整理

### 壁纸

壁纸、标题背景和 Palworld 标志服务于工具箱界面，不属于游戏版本事实。将旧 `资源包/壁纸` 迁入 `幻兽帕鲁/界面资源/壁纸`，更新壁纸管理和模式切换动画中的路径，不改变图片内容和显示效果。

### 旧地图目录

旧 `资源包/地图瓦片` 当前包含两类内容：

- 340 张以 `z...x...y...webp` 命名的旧背景瓦片；新版地图已经使用 1.0 的 WorldMap 和 TreeMap 瓦片，这些旧背景瓦片删除。
- 地图标记、工作图标、物品图标和辅助文件；其中仍被地图配置引用的图片迁入 1.0 的正式分类并更新引用，没有引用且无法确认用途的图片进入对应的待确认分类。

旧目录中的 `_make_white.mjs` 只在确认无人引用、且不再属于当前生成流程后删除。

### 旧图标资源包

旧图标多为 WebP，新版图标多为 PNG，不能仅按文件扩展名判断是否重复。分类时使用“不区分扩展名的文件主名”与新版数据字段进行比对：

- 新版已经存在正式对应文件：删除旧副本。
- 新版缺少、但当前程序仍引用：迁入 1.0 对应正式分类并更新引用。
- 新版缺少、当前没有引用、用途明确：迁入 1.0 对应正式分类。
- 新版缺少、当前没有引用、用途不明确：迁入原分类对应的待确认目录。

属性、工作和技能图标属于游戏版本资源，不继续留在无版本目录中。

### 新版图标错放

以 1.0 数据中的 `头像文件`、`图标文件` 字段作为正式归类依据：

- 物品图标中与帕鲁数据头像文件同名的图片属于帕鲁头像。如果帕鲁头像目录已有正式副本，删除物品目录中的重复副本；否则移动到帕鲁头像。
- 物品图标中与建筑数据图标文件同名的图片属于建筑图标，按同样规则去重或移动。
- 帕鲁头像中明显为人类、商人、士兵、博士、居民等 NPC 的图片移动到 `人物头像`。
- 帕鲁头像中无法确定是否属于帕鲁或人物的图片移动到 `帕鲁头像待确认`，不因为猜测而放入人物头像。
- 物品、建筑及其他分类中没有数据引用且用途不明确的图片分别进入本分类待确认目录。

NPC 的自动判断必须同时满足两个条件：图片没有被 `帕鲁.json` 的 `头像文件` 字段认领；文件名包含明确的人类或职业标识，例如 `CommonHuman`、`Male`、`Female`、`People`、`Soldier`、`Farmer`、`Doctor`、`Merchant` 或 `Ranger`。不满足这两个条件的帕鲁头像目录额外文件一律进入 `帕鲁头像待确认`，不根据外观猜测，也不自动删除。

### 新帕鲁子目录

`帕鲁头像/新帕鲁` 与根目录存在重复副本，并被开屏门面单独硬编码引用。将正式帕鲁头像统一到 `帕鲁头像` 根目录，更新门面路径后删除重复副本和空的 `新帕鲁` 目录。

## 删除与保留原则

允许删除：

- 已由 1.0 正式数据替代且业务代码不读取的旧数据。
- 内容有正式新版对应物的旧格式图片副本。
- 放错分类、而正确分类已有正式副本的重复图片。
- 已被新版地图替代的旧背景瓦片。
- 搜索确认无人引用、也不属于当前生成流程的临时辅助文件。

必须保留：

- 当前业务仍使用且尚未迁移完成的文件。
- 无法确认用途、又无法证明是重复的图片；放入带原分类名称的待确认目录。
- 1.0 正式数据字段指向的全部资源。
- UI 使用的壁纸和标志图片，只调整到界面资源目录。
- Leaflet、Three.js 等当前外部库，本次不移动也不升级。

## 引用更新

所有移动完成后，统一更新以下引用来源：

- `入口页面/index.html`
- 工作速度核心和通用逻辑中的浏览器及测试引用
- 壁纸管理和模式切换动画
- 地图核心中的默认图标表
- 帕鲁图鉴的属性、工作及来源图标路径
- 开屏门面的帕鲁头像路径
- 迁移复制脚本与迁移完整性检查
- 因正式目录变化需要同步的 `AGENTS.md` 结构地图

不保留指向旧路径的兼容分支；完成迁移后直接删除旧入口和旧目录。

## 自动检查

修改运行行为前先建立会失败的检查，至少覆盖：

1. 入口不再加载三个废弃旧数据。
2. 工作速度数据的新路径能同时被浏览器入口和 Node 测试环境找到。
3. 项目代码不再引用旧 `数据包`、旧 `图标资源包` 和旧 `地图瓦片` 路径。
4. 1.0 数据中所有帕鲁头像、物品图标和建筑图标字段都能解析到实际文件。
5. 物品图标正式目录不再包含被帕鲁或建筑数据认领的错放文件。
6. 明确 NPC 文件不再位于帕鲁头像正式目录。
7. 旧背景瓦片不存在，新版 WorldMap 和 TreeMap 瓦片完整。
8. 待确认文件只出现在与原分类对应的待确认目录。
9. 现有全部 JavaScript 自动检查继续通过。
10. 迁移完整性检查按新目录结构通过。

自动检查只验证可以客观判断的关系；无法客观判断的图片不自动删除。

## 肉眼验证

启动本机预览后：

1. 打开入口页，确认开屏帕鲁图片、背景壁纸和模式切换标志正常显示。
2. 进入网页模式，打开工作速度计算器，输入现有设施和等级，确认结果正常显示。
3. 打开帕鲁图鉴，检查头像、属性图标、工作图标及详情来源图片。
4. 打开物品、装备和建筑图鉴，检查列表、详情和材料图片。
5. 打开地图指南，切换 WorldMap 与 TreeMap，确认背景瓦片和地图标记都能显示。
6. 随机查看人物头像、正式分类和各分类待确认目录，确认没有建立总待确认目录。

## 不在本次范围

- 不修改工具 UI 布局和交互效果。
- 不修改游戏事实、计算公式和数据字段。
- 不升级或迁移外部库。
- 不重新设计图片内容。
- 不发布网站。
