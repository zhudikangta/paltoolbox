# 幻兽帕鲁 1.0 伙伴技能数据整理设计

## 目标与边界

本次整理伙伴技能数据和两个现有消费入口，并把帕鲁图鉴与伙伴技能工具统一成六项并列分类筛选；不改卡片样式和其他工具。对照来源是 PalDB 简体中文站，对应游戏版本为 `v1.0.0` 。

两个入口的职责分开：

- 帕鲁图鉴详情页按本站每个帕鲁 `id` 读取完整伙伴技能。Boss、塔主、狂暴、石板、手部、头部、召唤物和重复变体都保留，不因内容相同而省略。
- 伙伴技能工具读取生成目录。普通帕鲁全部列出；特殊类型只列出与普通原型有差异的记录，以及根本没有普通原型的记录。完全相同的 `_2` 等重复记录只在目录里保留一份。

## 数据分层

1. **原始来源**：保存抓取当时的 PalDB HTML 和来源清单，网站运行时不读取它。
2. **标准事实**：`伙伴技能.json` 以本站帕鲁 `id` 为唯一键，保存技能名、PalDB 中文效果描述、对应来源和核对状态。
3. **内部参数**：原有解包得到的类型、触发、冷却、消耗和五星数值放在独立的 `internalParameters` 对象中，不再冒充玩家可读描述。
4. **生成索引**：`catalog` 只保存应在伙伴技能工具出现的帕鲁 `id`、分类、原型和收录原因，由转换程序自动重建。
5. **冲突记录**：同一条事实在本站现有数据与 PalDB 不一致时写入 `conflicts`，不静默覆盖。Boss 与原型不同本身不算冲突，而是生成目录的正常依据。

## 获取与转换

使用 Node.js 自带的网络和文本能力，不安装额外解析库。普通帕鲁从 `https://paldb.cc/cn/Partner_Skill` 的 299 张卡片一次性提取。特殊差异记录从各自详情页提取；其他有普通原型且内部参数一致的记录，复用已核对的普通原型中文描述，但仍为每个帕鲁 `id` 写入一条完整事实。

转换程序必须可重复执行，并校验：

- 299 个普通帕鲁与 PalDB 一一对应，没有重名或遗漏。
- 标准事实覆盖本站全部帕鲁记录；PalDB 未收录或尚在调查的项目用明确状态表示，不编造说明。
- 伙伴技能目录的普通类完整，特殊类只有差异项和无原型项，完全相同的重复项不出现。
- 所有生成文件包含来源、获取日期、游戏版本和转换版本。

## 界面读取

帕鲁图鉴继续按当前帕鲁 `id` 读取 `partnerSkills[id]`，因此手、头、召唤物和重复 Boss 都能展示自己的完整记录。图鉴列表提供“普通帕鲁、石板Boss、塔主Boss、Boss、狂暴化、其他”六项并列筛选；普通帕鲁合并基础、亚种和泰拉瑞亚，不再保留子分类，默认顺序把泰拉瑞亚放在末尾，“其他”收纳变体和未归类记录。

伙伴技能工具根据 `catalog` 取数，不再直接遍历全部事实，并提供同名的六项并列筛选。普通帕鲁完整列出；五个特殊分类只展示目录中判定为有差异或没有普通原型的记录。

## 验证

自动检查覆盖 HTML 解析、名称对应、完整事实覆盖、Boss 差异保留、目录去重、两个入口的读取职责、六项筛选和现有迁移完整性。肉眼检查以棉悠悠、塞赫麦特、塔主荷鲁斯和月亮领主手部为代表，分别确认普通、差异、去重与无原型记录，并逐项点击两个页面的六类筛选。
