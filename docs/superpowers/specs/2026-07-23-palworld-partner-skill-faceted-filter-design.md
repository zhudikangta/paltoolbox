# 伙伴技能固定分面筛选设计

## 目标

把伙伴技能页现有的“左侧用途筛选 + 单独组合筛选”合并为一套固定侧栏筛选。用户既能一眼点开常用类别，也能跨类别组合条件，并且始终能看懂当前条件之间是“或”还是“且”。

本次只调整伙伴技能工具的分类语义、筛选交互和对应数据，不改伙伴技能描述、星级数值表、帕鲁来源六分类、图鉴详情页或其他工具。

## 已确认的筛选规则

1. 同一个筛面中的多个选项按“或”处理。例如同时选择“二段跳”和“三段跳”，结果包含任意一种。
2. 不同筛面之间按“且”处理。例如选择“地面骑乘”和“二段跳或三段跳”，结果必须同时满足骑乘方式与骑乘跳跃条件。
3. 页面不再提供独立的“组合筛选”模式。快速浏览和组合查询共用同一套条件、同一份状态和同一套结果。
4. 已选条件始终显示在结果区上方，可逐项删除，也可全部清空。
5. 结果摘要用自然语言说明当前逻辑，例如“地面骑乘，同时骑乘时可以二段跳或三段跳”。
6. 每个选项显示当前其他条件下的结果数量；数量为零的选项仍然可见，不能因已选大类而消失。

## 侧栏结构

侧栏顶部保留帕鲁来源六分类，并增加筛选项搜索。下方是固定的用途分组折叠区，默认展开当前相关分组，其他分组仍可随时打开，因此可以直接组合“移动与骑乘”和“战斗方式”等不同分组的条件。

“移动与骑乘”内部按用户实际问题拆成三个筛面：

- 移动方式：地面骑乘、飞行骑乘、水上骑乘、滑翔。
- 骑乘跳跃：骑乘二段跳、骑乘三段跳、骑乘高跳。
- 其他移动：玩家机动、特殊机动、传送与快速返回。

“多段跳”不再作为正式选项。它只是“二段跳或三段跳”的上位重复词，会制造重复结果和含糊语义。

## 分类语义

分类依据技能实际把能力赋予谁，而不是只匹配描述中的字词。

- “骑乘二段跳/骑乘三段跳”只收录玩家骑在该帕鲁身上时，坐骑本身获得相应跳跃能力的技能。
- 踏春兔让队伍中的玩家额外跳跃和空中冲刺；喵璐璐让队伍中的玩家低重力漂浮。两者统一归入宽泛的“玩家机动”，不拆成只有一条数据的独立筛选项。
- 跳板起跳、骑乘高跳等效果按实际用途归入宽泛但不混淆主体的选项。
- “可骑乘”只表示玩家能够骑到帕鲁身上；帕鲁站在玩家头上、载着玩家冲撞或让玩家腾出右手，都不能仅凭动作描述归入骑乘或指令攻击。

分类数据继续人工逐条确认。程序只负责读取已确认的事实、组合筛选和生成索引，不通过关键词自动决定技能语义。

## 数据与程序职责

- `伙伴技能分类.json` 是分类事实入口，保存每个伙伴技能的用途与精确能力标签。
- 筛面定义明确哪些能力属于同一个“或”集合；页面只读取定义并渲染，不在界面代码中猜分类。
- 核心筛选函数接收“按筛面分组的已选能力”。它对每个筛面执行任一命中，再要求所有已选筛面同时命中。
- 页面适配层只管理展开状态、筛选项搜索、已选条件和事件绑定。
- 卡片内容与现有伙伴技能详情继续复用，不复制描述或数值数据。

## 界面状态与反馈

- 来源、搜索文字、各筛面选项共同作用于同一结果集。
- 切换大类不会清除其他分组已经选择的条件。
- 已选项可在原位置和顶部已选区取消，两处操作修改同一份状态。
- 没有结果时保留全部筛选结构，并明确提示用户移除哪个条件或清空筛选，避免出现空白页面。
- 筛选项搜索只隐藏不匹配的选项，不改变已选状态和结果逻辑。

## 验证标准

自动检查必须覆盖：

- 同一筛面多选为“或”。
- 不同筛面同时选择为“且”。
- 地面骑乘与骑乘二段跳/三段跳可以跨筛面组合。
- 地面骑乘与飞行骑乘同时选择不会被解释成同时具备两者。
- 页面不存在独立组合筛选入口和旧的 `requiredCapabilityIds` 状态。
- 正式分类中不存在“多段跳”标签。
- 踏春兔和喵璐璐同属“玩家机动”，骑乘二段跳/三段跳只命中骑乘期间生效的技能。

肉眼验证时，在伙伴技能页依次选择“地面骑乘”、再选择“骑乘二段跳”和“骑乘三段跳”。结果摘要应明确显示跨筛面“且”、同一筛面“或”，卡片结果必须同时满足这两部分。随后同时选择“地面骑乘”和“飞行骑乘”，摘要必须表示二者是可选其一，而不是声称每张卡片同时具备两种骑乘方式。
